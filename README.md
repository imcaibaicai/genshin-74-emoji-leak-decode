# 原神 7.4「璃月加强」emoji 爆料图解码

`LICENSE: 待定`

## 这份工作的真正意义

本案的实际价值不在「解码了一组原神爆料」，而在于它是一次**多层级智能体协作的实战样本**：

- 一个**调度层**：只做任务拆解、定接口与产物路径、冻结符号口径、验收确定量，全程不碰执行。
- 若干**一阶负责人**：每人领一块互不重叠的维度，各自再往下派执行层子代理。
- 一批**取证型子代理**：负责单点抓取与核对，只回证据不回判断。

这套结构在一个**无码表、无权威源、证据碎片化**的问题上收敛出了可复核的结论：符号词典从 v1 迭代到 v5 才定型，四份角色线能在同一张横向表上逐格对比，每一格都能追到具体报告、具体引文。它同时也暴露了这套结构的失效点——写权限配错、子代理自报的证据不可采信、调用预算撞顶、派工信息错——记在第 5 节。那一节比结论更有参考价值：**能收敛**与**收敛过程可靠**是两件事。

## 1 这是什么

一次针对原神 7.4 版本「璃月角色加强」爆料图的**符号语言复原研究**：那批图不用文字，只用 emoji 与箭头描述命座、天赋、倍率的改动，本仓库记录的是把讨套自创符号一套套拆开、逐步定死含义、并标注哪些仍不确定的完整过程。

目标不是证明爆料为真。四张图是真是假，本仓库只给分层判断；真正的主张是**那套符号语言的语法可以被反推出来，且反推过程能被别人复查**。

除了分析与结论，本仓库还附带**未加工的协作流水**（`trace/`）：从拆任务、派工、跑偏到被打回重派，每一步原始事件都在里面，可以与 `docs/`、`chars/` 的分析结论对照阅读——结论是否真跑出来的，读者自己判断。

## 2 结论摘要

四角色的改动方向，各一句：

- **甘雨**：霜华矢冰伤与冰莲／领域数值上调，E 增加「缩短蓄力」方向，C4 每层 5%→10%、上限 25%→50%，C6 在窗口内把蓄力时间归零——中幅、方向明确，但不改角色结构。
- **魈**：E 可用次数 2→3，C2 把充能从「自身后台」改成全队受益，C4 是**移除**原有的防御 +100%（不是改值），C6 把敌人数门槛从 2 降到 1。
- **胡桃**：重击（Z）与元素爆发（Q）改走「大权」倍率乘区，并按队伍内璃月角色 2 名／3 名分两档；这条原本是全批唯一「机制级已核」，出处被证伪后降为**推断**。
- **夜兰**：E 次数 1→2 并新增破局矢强化，Q 的叠层与骰子本体上调，A1 四档生命上限上调——改动面最宽，可信度最低。

可信度分层（由强到弱）：

1. **甘雨最高**：一手名单点名，公众号 4/4，四条命座硬锚（c1／c2／c4／c6）逐条对得上。
2. **魈次高**：同一手名单点名且被主动数出，4/4，C1 的次数与 C6 的敌人门槛严丝合缝。
3. **胡桃中等**：一手名单明确说「胡桃这边我没听说过」，公众号 2/4 且其中一份明写未上榜；符号层自评最干净，名单层最弱。
4. **夜兰最低**：一手名单连提都没提，公众号 0/4，且传播侧标题自认是「夜兰加强玩家整活」。

分层的关键判据是：**「像真的」与「是真的」是两件事**。符号自洽度与名单证据强度在四张图上不同向，不能互相顶替。

## 3 调度结构

取证本身仍走三步，顺序不能换：用真实命座原文反推符号、用开源数值库与社区公式站建立基线、多路互斥维度并行取证再交叉（明细见 `docs/00-lexicon-scout.md` 至 `docs/17-yelan-debunk.md`）。三步之外，真正决定成败的是下面这套调度结构。

- **峰值并行**：五路取证（贴吧／NGA／Reddit／Telegram／公众号）与四条角色线（甘雨／魈／胡桃／夜兰）同时跑，全程派工三十余个子代理。并行是默认状态，串行才需要说明理由。
- **维度互斥**：每次并行前先划清「谁负责什么、明确不负责什么」，禁止同一个 query 派两路。互斥不是为了省事，是为了让两路结果能直接对照——两路抓同一处，只会得到两份互相污染的抄本。
- **接口先行**：动手前先定产物路径、固定小节名、JSON 字段与 `EVIDENCE` 行格式。没有这些约定，几路结果回头合不拢，横向表也无从拼起。
- **写者唯一**：同一文件同一时刻只许一个子代理写。多人同写同一份 md 的结果是互相覆盖，且事后无法判断谁的版本是最终版。
- **单一裁决权**：符号词典经历 v1 到 v5 五次改版，每次都由调度层统一改版并广播，各线不得私改口径。这是四条角色线最终能横向对比的唯一保障。
- **失败必须显式**：取证受阻要回报「阻塞点 ＋ 已尝试 ＋ 需要什么」，不许静默降级成一句「没找到」。`docs/19-nga-page-e.md` 里那几个页码的内容只差 8 字节，就是一路查到底才确认的现象。

配套的定级纪律：一个符号至少两条独立证据才能写「已核」，只有一条写「暂定」，一条也没有写「未决」——`🪜`、`🔮`、`💨` 至今停在这一步。

四条结构规则比单符号更有迁移价值：

1. **图头部的 emoji 是身份谜面，不参与机制映射。** 甘雨头部 🥥🐐、魈头部四符在正文里零出现。
2. **部位标签一律带冒号，不带冒号的是数值量。** 已知带冒号的是 `❄️🏹 :`、`🧊🪷 :`、`🧊☁️ :`、`🧵 :`、`🎲 :`；`🪜` 五次出现全无冒号，这是它被排除出「部位标签」读法的依据。
3. **无标号行按上下文归入相邻命座**，多为该命座的追加效果。6.2 那批的官方写法就是「旧效果保留＋此外新增一条」。
4. **`→` 只用于旧值改新值，`+` 才表示新增**，这是判断「改值」还是「加一条」的第一道分水岭。

## 5 已知缺陷

这一节是这份研究的实际状态，不做粉饰。

- **所有 `?` 位置的数值仍然是空的。** 图面上就是留白，一个真实数值都没拿到：胡桃 Z 与 Q 的两档倍数、甘雨 C1 回能、甘雨 C4 的减防百分比、夜兰的羽毛额度，全部只有「候选：低／中／高」的推演区间。表里出现的区间是**推演**，不是爆料值。
- **`🪜`、`🔮`、`💨` 三个符号未决。** `🪜` 剩两个候选（璃月档位／次数），`🔮` 只知道它挂在魈 C6 那条线上的某处，`💨` 连候选都没稳定下来。
- **有三个假设被自己推翻过。** `🌙` 最初读成「月曜反应体系」，后改为「璃月」；`⭐` 最初读成「固有天赋段标」，后改为「辉映·星烁体系」；`🪶` 最初读成「破局矢」，后改为「羽毛区」。三次都是后续取证推翻了先前更像直觉的读法，`docs/99b-v5-修订与终局判定.md` 逐条记了更正依据。
- **一段被当作硬证据的 NGA 文字版出处已证伪。** 曾被引用为「编号条目第 6 条」的那段文字，实测该帖（`tid=47985638`）主楼只有五个字加一个附件、全帖 12 层 2101 字、编号条目零命中，判定为搜索摘要挂错了 URL。连带后果：胡桃那条「跨载体互证」作废、置信度由「已核」降为「推断」，依赖它的「璃月人数是覆盖全部改动的前置门」也一并降级。详见 `docs/99c-来源勘误.md`。
- **社区对这批爆料本身有打假声音。** 同一讨论串里三条原话：「编料也太喜欢暴击转暴伤了」「贴吧编制出口转内销的」「我不信，目前所有加强都是原本的基础上额外加东西」。第三条还是对本报告的方法论反证——社区经验是同类加强只做加法，而本报告对魈 C4 的判读是「移除」，据此该条也降为「推断」，并保留「`🛡️↓` 指降低敌人防御」的另一种读法。
- **三处并列冲突未裁定**，留在 `docs/99b-v5-修订与终局判定.md` 第 7 节：甘雨 C4 取消叠层与图上两个数的矛盾、魈的抗打断方向与 `💨↓` 的矛盾、夜兰的名单归属冲突。

以上是**内容层**的缺陷。还有一层是**方法论层**的代价，这部分才是这个样本最有参考价值的内容，不作美化：

- **写权限配错**：三个取证子代理的 preset 没有写权限，成果只能回到调度层，两份报告事后补写。派工前没核对权限，等于让执行层白跑一趟取证。
- **子代理自报的证据不可采信**：`EVIDENCE` 行的字节数与哈希不能直接采信——「正文末尾换行算不算正文」的口径各线不一，实测偏差 1 至 3 字节。最终改为由调度层统一测量后才入表。
- **预算撞顶**：部分子代理撞满 9 次工具调用预算，交回半成品。预算不是提示词里的软建议，是真会截断交付的硬边界。
- **派工信息错**：数值基线那一路第一次派工用错了仓库名，7 次 404，重派成两路才成。派工单里的外部标识（仓库名、tid、URL）必须由调度层核过再发。

## 7 如何复现

**能复现的部分（离线，不需要账号）：**

1. 符号反推。四名角色的命座与天赋原文是公开的，按 `docs/00-lexicon-scout.md` 的符号清单逐位置对照，可以独立得出同一批锚点。
2. 数值基线。gcsim 是开源的，社区公式站公开可访问；`docs/04a`、`docs/04b` 的每个旧值都能复核。`docs/14-feather.md` 里「羽毛按命中段数逐段消耗」这个判定，直接读 gcsim 源码就能验证。
3. 横向对比。`docs/99-cross-table.md` 的每一格都能追到某份报告，报告里的引文都能追到公开帖。

**依赖当时帖子的部分（可能已经不可复现）：**

1. NGA 帖 `tid=47985638` 本身只有五个字加一个附件，报告据此判定搜索摘要挂错了 URL。这个「没有正文」的结论**依赖当时那一版页面**，帖子被删或补上正文后就不成立。
2. 贴吧检索当时零命中，原帖现在大概率已删。
3. 各站的搜索摘要会漂移，`docs/08-textver-hunt.md` 记录的那次「摘要与 URL 不匹配」就是活例。

**脚本的运行前提：**

`scripts/*.mjs` 需要 ego lite（Chromium 自动化工具）与一个**已登录的百度／NGA 环境**。脚本里的输出目录与素材目录已改成相对路径（`./`、`./out/`、`../assets/more/`），**使用前请改每个脚本开头几个常量**（`const DIR`、`const OUT`、`const MORE`、`const REP`），指向你自己的目录。另据实测：NGA 站内搜索要求注册用户且威望大于 0，游客返回 `ERROR:2048`；`bbs.nga.cn` 主域会被广告插播页劫持，只有 `ngabbs.com` 镜像可读，且该镜像对不存在的页码会回落（`page=2`、`page=3`、`page=e` 内容几乎相同，只差 8 字节）。
